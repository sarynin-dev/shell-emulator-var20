# Эмулятор командной оболочки (вариант 20)

Консольный эмулятор оболочки UNIX-подобной ОС на Python 3
(без сторонних зависимостей).

## Общее описание

Эмулятор работает как командная строка UNIX: приглашение
`username@hostname:~$` строится из реальных данных ОС, ввод разбивается
на команду и аргументы по пробелам, команды работают с виртуальной
файловой системой (VFS), загруженной из JSON-файла в память. Все
изменения (`chmod`, `chown`) выполняются только в памяти — файл VFS
на диске никогда не изменяется.

Работа выполнена в 5 этапов, каждый этап — отдельный коммит:

1. REPL — приглашение, парсер, заглушки `ls`/`cd`, `exit`.
2. Конфигурация — параметры `--vfs`, `--script`, стартовый скрипт.
3. VFS — загрузка из JSON, base64 для двоичных данных.
4. Основные команды — `ls`, `cd`, `cat`, `tree`, `uniq`.
5. Дополнительные команды — `chmod`, `chown`, `vfs-load`, `help`.

## Структура проекта

```
src/shell_emulator/   исходный код
  __main__.py         точка входа, загрузка VFS, запуск скрипта и REPL
  config.py           параметры командной строки
  shell.py            цикл REPL и выполнение стартового скрипта
  parser.py           разбор строки на команду и аргументы
  prompt.py           приглашение из данных ОС
  vfs.py              виртуальная файловая система
  options.py          разбор флагов и общие проверки команд
  fs_commands.py      ls, cd, cat, tree, uniq
  perm_commands.py    chmod, chown
  commands.py         реестр команд, help, vfs-load, vfs-info, exit
tests/                модульные тесты (unittest)
vfs/                  варианты VFS в формате JSON
scripts/              стартовые скрипты эмулятора (*.vsh) по этапам
os_scripts/           скрипты ОС, запускающие эмулятор с разными
                      параметрами (*.sh — Linux/macOS, *.bat — Windows)
```

## Команды

| Команда                                | Описание                        |
|----------------------------------------|---------------------------------|
| `ls [-a] [-l] [путь...]`               | содержимое каталога             |
| `cd [путь \| ~ \| -]`                  | смена текущего каталога         |
| `cat [-n] файл...`                     | вывод содержимого файлов        |
| `tree [-d] [путь]`                     | дерево каталогов                |
| `uniq [-c] [-d] [-u] [-i] файл`        | удаление соседних повторов      |
| `chmod [-R] РЕЖИМ файл...`             | смена прав доступа              |
| `chown [-R] ВЛАДЕЛЕЦ[:ГРУППА] файл...` | смена владельца и группы        |
| `vfs-load путь`                        | загрузка новой VFS с диска      |
| `vfs-info`                             | сведения о текущей VFS          |
| `help [команда]`                       | список команд с описанием       |
| `exit [N]`                             | выход с кодом возврата `N`      |

Подробнее о флагах:

- `ls`: `-a` — показать скрытые файлы и `.`/`..`, `-l` — права,
  владелец, группа, размер. Сначала выводятся файлы, затем каталоги;
  при нескольких операндах у каталогов печатается заголовок.
- `cd`: без аргумента — в домашний каталог, `-` — в предыдущий.
- `cat`: `-n` — сквозная нумерация строк. Текст может храниться в VFS
  как обычной строкой, так и в base64; двоичные файлы не выводятся.
- `tree`: `-d` — только каталоги; в конце — число каталогов и файлов.
- `uniq`: `-c` — количество повторов, `-d` — только повторяющиеся,
  `-u` — только уникальные, `-i` — без учёта регистра.
- `chmod`: восьмеричный режим (`755`) или символьный (`u+x`, `go-w`,
  `a=r`, несколько через запятую); `-R` — рекурсивно.
- `chown`: `alice`, `alice:staff` или `:staff`; `-R` — рекурсивно.
- `vfs-load`: при ошибке загрузки остаётся прежняя VFS.

Пути: абсолютные, относительные, `.`, `..`, `~`. Флаги можно
объединять (`ls -la`). Коды возврата: 0 — успех, 1 — ошибка,
2 — `ls` не нашёл путь, 127 — неизвестная команда
(`foo: command not found`).

## Параметры командной строки

| Параметр         | Описание                                        |
|------------------|-------------------------------------------------|
| `--vfs PATH`     | путь к физическому расположению VFS (JSON)      |
| `--script PATH`  | стартовый скрипт с командами эмулятора          |

При запуске выводятся все параметры (`[config] ...`). Без `--vfs`
используется пустая VFS из одного корневого каталога.

Стартовый скрипт показывает каждую команду с приглашением и её вывод,
имитируя диалог с пользователем; строки на `#` — комментарии.
Выполнение останавливается на первой ошибке, эмулятор завершается с её
кодом. Если скрипт не завершился командой `exit`, после него
открывается интерактивный режим.

## Виртуальная файловая система (VFS)

```json
{
  "home": "/home/user",
  "root": {
    "type": "dir", "owner": "root", "group": "root", "mode": "755",
    "children": [
      {"name": "a.txt", "type": "file", "content": "текст"},
      {"name": "b.png", "type": "file", "content_base64": "iVBORw0K"}
    ]
  }
}
```

| Поле              | Описание                                           |
|-------------------|----------------------------------------------------|
| `home`            | домашний каталог (`~`), необязательно; иначе `/`   |
| `type`            | `dir` или `file`                                   |
| `name`            | имя узла (у корня не указывается)                  |
| `mode`            | права в восьмеричном виде, по умолчанию 755 / 644  |
| `owner`, `group`  | владелец и группа, по умолчанию `root`             |
| `children`        | содержимое каталога                                |
| `content`         | текст файла (UTF-8)                                |
| `content_base64`  | содержимое файла в base64 (двоичные данные)        |

Варианты VFS в каталоге `vfs/`:

- `minimal.json` — только корневой каталог;
- `few_files.json` — несколько файлов, в том числе двоичные;
- `deep.json` — 6 уровней вложенности, домашний каталог `/home/user`;
- `broken.json`, `not_json.json` — некорректные, для проверки ошибок.

## Сборка, запуск и тесты

Сборка не требуется, нужен только Python 3.8+.

```sh
./run.sh                                  # интерактивный режим
./run.sh --vfs vfs/deep.json              # с VFS
./run.sh --vfs vfs/deep.json --script scripts/stage5.vsh
./test.sh                                 # модульные тесты
```

В Windows: `run.bat` с теми же параметрами.

Скрипты ОС для проверки этапов (запускаются из любого каталога):

```sh
./os_scripts/test_stage2.sh   # все параметры командной строки
./os_scripts/test_stage3.sh   # разные варианты VFS и ошибки загрузки
./os_scripts/test_stage4.sh   # ls, cd, cat, tree, uniq и их ошибки
./os_scripts/test_stage5.sh   # chmod, chown, vfs-load, help и ошибки
```
